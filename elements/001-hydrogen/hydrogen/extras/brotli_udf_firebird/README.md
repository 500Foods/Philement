# Brotli Decompression UDR for Firebird

This directory contains the Firebird User-Defined Routine (UDR) for Brotli
decompression, used by the Helium migration system to decompress large
base64-encoded Brotli strings stored in the `queries` table.

## Overview

Firebird 4 has no native Brotli decompression. Like the other engine extras
(`brotli_udf_postgresql`, `brotli_udf_mysql`, `brotli_udf_sqlite`,
`brotli_udf_db2`), this UDR wraps the `libbrotlidec` library to provide
transparent decompression of migration data.

The UDR is loaded into Firebird's UDR engine (not the legacy UDF mechanism,
which is deprecated since Firebird 4). It uses the Firebird Object-Oriented
API via `UdrCppEngine.h`.

## Dependencies

- **Firebird 4.0** development headers (`firebird-devel` package on Fedora)
- **libbrotli** decompression library (`libbrotlidec`)
- A C++ compiler (`g++`)

### Installing Dependencies (Fedora)

```bash
sudo dnf install firebird-devel libbrotli-devel gcc-c++
```

## Building

```bash
make clean
make
```

This produces `brotli_decfn.so` — the shared library loaded by Firebird's UDR
engine at runtime.

## Installation

```bash
sudo make install
```

This copies `brotli_decfn.so` to the Firebird UDR plugin directory
(default: `/plugins/udr`). If your Firebird installation uses a different
path, override it:

```bash
sudo make install UDR_DIR=/var/lib/firebird/plugins/udr
```

## Registering the Function

The UDR is registered automatically by migration `acuranzo_1000.lua` via the
`${BROTLI_DECOMPRESS_FUNCTION}` macro defined in `database_firebird.lua`:

```sql
CREATE OR ALTER FUNCTION BROTLI_DECOMPRESS(compressed BLOB)
RETURNS BLOB
EXTERNAL NAME 'brotli_decfn!brotli_decompress'
ENGINE UDR;
```

**External name format:** `<module>!<routine>` where:

- `module` = shared library basename without `.so` (`brotli_decfn`)
- `routine` = function name registered by `FB_UDR_BEGIN_FUNCTION` (`brotli_decompress`)

## Usage in Migrations

The Brotli decompression is invoked automatically when processing compressed
migration code:

```sql
-- Generated by ${COMPRESS_START}...${COMPRESS_END}
INSERT INTO queries (code) VALUES (
    BROTLI_DECOMPRESS(BASE64_DECODE('...'))
);
```

The Helium Lua migration system compresses strings > 1KB at generation time
using Brotli quality 11. This UDR only decompresses — the Lua side handles
compression.

## Testing

### Test Fixture

`test_brotli.sql` contains a fixture that compresses a known string with
Brotli quality 11, base64-encodes it, and verifies that
`BROTLI_DECOMPRESS(BASE64_DECODE(...))` returns the original text.

### Running Tests

```bash
# Ensure Firebird is running and UDR is installed
isql-fb -user SYSDBA -password <password> testfb.fdb < test_brotli.sql
```

### Quality 11 Round-Trip

The test data uses the same Brotli quality 11 compression as the Lua
migration system. The base64-encoded compressed data is generated by:

```lua
-- Lua (quality 11, matching the migration system)
local data = "[=[large SQL DDL]=]"
local compressed = brotli.compress(data, 11)
local encoded = base64.encode(compressed)
```

## How It Works

The UDR reads its input BLOB via the Firebird OO API (`IBlob::read`),
decompresses using `BrotliDecoderDecompressStream`, and writes the result
to the output BLOB (`IBlob::write`). The decompression loop handles
`BROTLI_DECODER_RESULT_NEEDS_MORE_OUTPUT` by growing the output buffer,
matching the pattern used by the PostgreSQL, MySQL, and SQLite extras.

## Comparison with Other Engine Extras

All engine extras share the same core Brotli decompression logic. The
differences are in the host API:

| Engine | API | Memory | Error Handling |
| --- | --- | --- | --- |
| PostgreSQL | `PG_FUNCTION_INFO_V1` / `Datum` | `palloc` / `pfree` | `ereport(ERROR, ...)` |
| MySQL | `UDF_INIT` / `UDF_ARGS` | `malloc` / `free` | `is_null` / `error` flags |
| SQLite | `sqlite3_context` | `sqlite3_malloc` / `sqlite3_free` | `sqlite3_result_error` |
| DB2 | `SQL_API_FN` | DB2 heap | `SQLUDF_STATE` |
| **Firebird** | `FB_UDR_BEGIN_FUNCTION` / OO API | `malloc` / `free` | Throw `FbException` |

## Troubleshooting

### Error: "function UDR is not registered"

The UDR library is not in the Firebird UDR directory or the external name
format is wrong. Verify:

- `brotli_decfn.so` is in `/plugins/udr/` (or your configured UDR dir)
- The `EXTERNAL NAME` uses `brotli_decfn!brotli_decompress` (module!routine)
- Firebird has the UDR engine enabled (`UdrEngine = true` in `firebird.conf`)

### Error: "symbol not found"

The UDR was compiled with a different compiler or ABI. Use the same GCC
version as your Firebird installation and ensure `-std=c++11` or later.

### BROTLI_DECOMPRESS returns NULL

Verify the input data was compressed with Brotli quality 11 and is
base64-decoded before passing to `BROTLI_DECOMPRESS`. Use the DB2-style
combined function if you need a single-step base64+decompress.
